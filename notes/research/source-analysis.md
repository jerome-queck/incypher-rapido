# IN-CYPHER source analysis

Research date: 2026-09-15 (SGT). Read-only review of [`incypher-ctf`](https://github.com/jerome-queck/incypher-ctf), main at [`892c764`](https://github.com/jerome-queck/incypher-ctf/commit/892c764ba65751af31c59386e27fdf05523e162e), [`issue #256`](https://github.com/jerome-queck/incypher-ctf/issues/256), and its execution tickets (#300, #301, #302, #304, #307, #320, #323). The destination already uses `notes/research/`; no credentials, flags, or live Board mutations were used.

## Executive summary

The source’s intended product is one unattended Docker run that discovers the official Board set, solves static and isolated challenges, and submits flags with an auditable, replayable record. Its central design is not “an LLM with tools”: it is a supervised object graph with one canonical writer, typed authority brokers, durable reservations before external effects, two bounded solving lanes, and serial submission.

The most important integration boundary is the Board profile. Authentication is host-bound `Authorization: Token …`, browser-like JSON transport with redirects disabled, and a two-cycle qualification step that rejects login HTML, synthetic empty collections, inconsistent identity, or malformed schemas. Native Codex is similarly brokered: the owner invokes `codex exec --json` using a `CODEX_HOME/auth.json` subscription session; child workers receive an allowlisted environment and opaque capabilities, never Board tokens or model keys.

Issue #256 describes the final 5.5-hour gate and 15 official practice challenges. The linked implementation tickets cover the intended surfaces, but #302, #304, #307, #320, and #323 were still open when inspected. Therefore the source is a detailed production design and substantial substrate, not proof that every final gate assertion has passed.

## Board API, authentication, and dynamic targets

[`solver/board.py`](https://github.com/jerome-queck/incypher-ctf/blob/main/solver/board.py) hard-codes the observed CTFd/chall-manager surfaces: challenge list/detail, scoreboard, `/users/me`, instance ledger, mana, deploy/renew/restart/destroy, attachment downloads, and `POST /api/v1/challenges/attempt`. API redirects are never followed because a login `302 → 200` HTML response can otherwise look like an empty successful read. Requests use a browser UA, `Accept: application/json`, `Content-Type: application/json`, and `Authorization: Token …`; the token is sent only to the configured Board host. File downloads are the exception and have a 256 MiB cap plus bounded redirect handling.

The profile treats an empty list as untrusted. It requires a real JSON 404 negative control, authenticated-vs-anonymous distinction, stable identity/window markers, two-cycle equality, per-ID details, and ledger identity consistency. The source’s #301 audit found a concrete edge failure: the collection path omitted `Content-Type` on authenticated landing/ledger reads, causing profile refusal. It also found a known-invalid Challenge-field query that returned the same synthetic empty projection as anonymous scoreboard/team/user queries; catch-all emptiness cannot establish Board truth. The current client contains the stricter transport and qualification logic.

All Board effects pass through [`BoardBrokerRuntime`](https://github.com/jerome-queck/incypher-ctf/blob/main/solver/board_broker.py). It authenticates peers, requires the qualified profile, reserves durable intent before an effect, records/redacts/seals response bodies, classifies malformed/timeout/auth/Board/unreachable outcomes, and returns an indeterminate state when durability fails. Dynamic instances are generation-fenced and owned by one lease coordinator; renew/restart/terminate require observed ownership and reconciliation.

## Native Codex integration and auth

[`solver/codex.py`](https://github.com/jerome-queck/incypher-ctf/blob/main/solver/codex.py) invokes the vendor CLI (`codex exec --json`) rather than an SDK or API key. The credential is a model plus `CODEX_HOME`; auth is the subscription file `CODEX_HOME/auth.json`. Prompts and images are passed through stdin/staged paths. The child environment is an allowlist (`PATH`, `HOME`, `TERM`, `LANG`, `CODEX_HOME`), with no Board token, CPA secret, LLM key, or target URL.

[`solver/codex_control.py`](https://github.com/jerome-queck/incypher-ctf/blob/main/solver/codex_control.py) exposes an opaque `codex.engage` capability over a peer-authenticated Unix socket. It serializes calls, freezes the model/effort catalogue, validates response IDs and usage, records observed limits, and rejects uncleared secret surfaces. Exhaustion/usage-limit signals trigger bounded chain handoff; generic failures are classified, not blindly retried. Prior research records killed invocations with missing usage, empty progress, and duplicated work, plus malformed/quota failures in experimental OMP/OpenCode paths; those are not alternate auth routes ([ADR-0039](https://github.com/jerome-queck/incypher-ctf/blob/main/docs/adr/0039-native-codex-leads-and-one-small-loop-owns-the-cpa-route.md), [agent-loop audit](https://github.com/jerome-queck/incypher-ctf/blob/main/docs/research/2026-09-05-agent-loop-productivity.md)).

The invocation currently declares `danger-full-access` and root challenge execution inside a container boundary. Issue #256’s final invariant is stricter hostile-execution isolation; the outer attempt executor/cgroup and broker boundaries, not the Codex CLI flag alone, are what provide that safety model.

## Artifacts and tool supply

The release model is one immutable multi-architecture image with resident, pinned, real-input-proved tools; runtime installers and ad-hoc shell authority are excluded ([ADR-0047](https://github.com/jerome-queck/incypher-ctf/blob/main/docs/adr/0047-one-immutable-image-exposes-only-proved-free-tool-components.md)). The inventory covers HTTP/TCP and SQLite, process inspection, archive/rootfs and package formats, ELF/recon, image/PDF/document inspection, OCR/barcode, crypto/math/SMT, and bounded parsers. Profile overlays add crypto, web, pwn/reverse/foreign-ELF, forensics/disk, stego/media, OSINT, AI/ML, protocol, and mobile-static capability sets.

Tools are exposed through typed handles with run/boot/generation/lane/attempt/step binding. Attachments and target connections carry provenance; target-bound DNS/SNI/cert and network sessions prevent a generic worker from escaping its assigned target. The linked tickets specify HTTP discovery/session operations, raw and framed binary TCP, ELF/debug/ROP workflows, signed packages, ZIP CRC/metadata, read-only ext4 recovery, DICOM metadata, WAV signal/bitstream, and bounded parsers. #302, #304, and #307 remain the relevant implementation-completeness tickets.

## Concurrency, lifecycle, and persistence

The lane controller uses a bounded `ThreadPoolExecutor`, fills free lanes from a freshly computed order, and drains first-completed work. Admission reserves Lane → Work generation → binding before execution. A worker that outlives its process consumes that lane for the cycle; interrupted lanes are fenced and never resumed. Every attempt releases its lease, and terminal shutdown performs cleanup/reconciliation.

The event store writes `/state/runs/<run_id>/canonical/events.jsonl` and sealed blobs under file locks, with exact identity idempotence, contiguous sequence/previous-digest checks, `write + fsync` and directory fsync. Replay verifies event/blob digests, schema, lengths, torn appends, and release tombstones. The candidate manifest is deterministic and cannot be claimed until its requirements and receipts are sealed. Submission policy is deliberately conservative: one POST per step, bounded incorrect attempts, a per-challenge/account rate limit, and no resend after an unknown outcome ([ADR-0037](https://github.com/jerome-queck/incypher-ctf/blob/main/docs/adr/0037-submission-is-speed-first-provenance-backed-and-serial.md)).

## Known failures, gaps, and source caveats

- The 14-Sep practice release was read-only except for one deliberately wrong probe caused by an initial missing `--no-attempt` guard; no instance lifecycle mutation was performed. Deploy/renew/restart/destroy, connection delivery, PoW, ownership, and real cleanup therefore remain unverified in that research note ([practice release](https://github.com/jerome-queck/incypher-ctf/blob/main/docs/research/2026-09-14-in-cypher-practice-release.md)).
- Official duration and wrapper/flag descriptions conflict; ADK/demo and the PoW helper were not linked. Practice data includes answer-bearing descriptions (for example, a published ZIP write-up/flag), so it is unsuitable as an unfiltered discovery/evaluation corpus.
- The main issue’s final gate requires a held-token run over all 15 practice challenges, static plus isolated targets, at least five flags across three categories, no human intervention, and a truthful failure/conflict record. The linked gate and capability tickets were not all closed at inspection; do not infer completion from the presence of the substrate.
- The source’s strongest reusable lesson is boundary discipline—canonical ownership, reservation-before-effect, brokered secrets, typed target handles, and replay—not a mandate to copy its model, policy, or ticket scope into another project.
