## Failure path and repair

`BoardClient._document` treated readable HTTP 502 as a generic semantic `BoardError`.
`Orchestrator._board_read` retries only closed retryable classes, and the active/idle Board
watchers back off only after those classes. One 502 from the active challenge-list watcher
therefore escaped the watcher and failed the whole run. This is distinct from malformed or
incoherent Board data, which must still fail closed.

The repair classifies HTTP 500/502/503/504 on idempotent Board reads as a separate temporary
response. The existing bounded read retry and watcher backoff handle that class; persistent
watch read outages do not cancel productive solver work. Anonymous identity, challenge catalogue,
challenge detail, instance GET, and file GET use this classification. The initial attachment
download still has one attempt; it does not enter the watcher retry loop. Submissions and instance mutations
are unchanged: no ambiguous write is retried automatically, and an unread submission cannot
become a correct verdict. Redirect and malformed-response checks remain fatal. Focused tests
cover read classification, non-retried mutations, bounded attempts, active and idle watcher
recovery, and the existing semantic-failure path.
