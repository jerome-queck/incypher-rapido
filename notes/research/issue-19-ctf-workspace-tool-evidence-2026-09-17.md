## Scope and decision rule

This note records tools that a Codex or Claude solve actually executed or imported on a successful
derivation path. It does not infer use from an install manifest, `solved_by`, or a writeup's list of
alternatives. Manual CTFd submission is separate from solver derivation: an agent-derived candidate
still counts when an operator only confirmed it on the Board. Tools that merely supported manual
interpretation, occurred only in failed exploration, or cannot yet run in Rapido's final Linux
container are retained below as deferred evidence rather than promoted to core.

Rapido remains responsible for proving all four layers separately: installed, model-visible,
authorized, and semantically working. Every retained tool therefore needs a bounded functional
wrapper and a semantic receipt; `--help` or import success alone is insufficient.

## Rapido compatibility and acceptance constraints

Rapido currently targets Debian Bookworm, Python 3.12, amd64 and arm64, and runs as UID 10001
with no login shell (`Dockerfile:3-7,38-68,93-107`). Its current Python pins include Capstone 5.0.9
and Unicorn 2.1.2 (`pyproject.toml:12-23`). Therefore:

- isolate angr and Sage/fpylll rather than destabilizing the main venv;
- build or acquire native artifacts for both target architectures; never reuse the checked-in
  CPython 3.10 x86-64 lattice wheels;
- give hashcat CPU OpenCL explicitly; assume no GPU;
- share one pinned headless JRE between Ghidra and jadx only after both semantic fixtures pass;
- vendor Foundry, TON, webcrack, browser, wordlist, and database assets at build time; no runtime
  package download or arbitrary internet;
- keep tshark read-only and unprivileged, recursive archive extraction bounded, and every parser in
  the artifact worker;
- expose the tools through scriptable bounded interfaces and persist version plus semantic receipts.
